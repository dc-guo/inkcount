# Phase 0 — Dependable InkCount Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make InkCount dependable where students are: CI protecting `main`, offline-capable PWA, accessibility, a phone self-test page, honest Beta labeling, and an intake path for real-handwriting fixtures.

**Architecture:** The existing scratchpad CDP harness moves into `tools/ci/` as a zero-dependency Node script with its own static server; GitHub Actions runs it before every Pages deploy. A service worker (versioned precache for the shell, cache-first for the 80 MB of vendored runtime) makes repeat visits offline and replaces manual cache folklore. Accessibility and device testing are additive pages/markup, no pipeline changes.

**Tech Stack:** Node ≥20 built-ins only (no npm deps in CI), GitHub Actions `ubuntu-latest` (Chrome preinstalled at `google-chrome`), vanilla service worker, axe-core (vendored single file, dev/test only).

## Global Constraints

- Zero-backend covenant (plan §3): no accounts, no uploads, no analytics; everything served from own origin.
- All asset paths relative; site must work at `https://dc-guo.github.io/inkcount/` and `http://localhost:8000/web/`.
- The 9 existing gates (smoke, assets, count, decode, preprocess, segment, recognize, accuracy) plus the 11-step UI walkthrough must stay green throughout.
- Service-worker scope is `/inkcount/` in production and `/web/` locally — all SW URLs must be derived relative to `self.registration.scope`, never absolute.
- Version stamp discipline: `meta[name=inkcount-version]`, `APP_VERSION` in `web/src/ui.js`, and the SW `CACHE_VERSION` bump together every release (this plan ships as version 6).
- Copy rule (plan §4 P0): the words "Proof of concept" disappear from the product UI; the badge reads "Beta"; accuracy copy states synthetic and real numbers separately.

**Interfaces:**
- Produces: `navigator.serviceWorker.register('./sw.js')` from `index.html`; SW message `{type:'SW_UPDATED'}` → UI shows "InkCount updated — reload to apply" banner reusing `#error-banner` styling with an action button.

- [ ] **Step 1:** Generate the two icons from the existing ink-drop SVG favicon (render at 192/512 via the headless-Chrome screenshot trick or PIL) — solid `#2f6fed` rounded square, white drop.

- [ ] **Step 3:** `web/sw.js`: `CACHE_VERSION = 'v6'`; **precache** (install): `./`, `index.html`, `styles.css`, `app.js`, all `src/*.js`, `manifest.webmanifest`, icons, `samples/sample_page.jpg`; **runtime cache-first** (fetch): anything under `vendor/` (opencv, transformers bundle, wasm, model files — too big to block install on); network-first for navigations with cache fallback; `activate` deletes caches ≠ `CACHE_VERSION`, `clients.claim()`, then `postMessage({type:'SW_UPDATED'})` to clients when a previous version existed.
- [ ] **Step 4:** Registration block in `index.html` (feature-detected, after load); in `ui.js` boot: `navigator.storage?.persist?.()` fire-and-forget (guards model eviction), and a listener for `SW_UPDATED` showing the reload banner.

- [ ] **Step 6:** Commit; push; confirm CI green including the new `pwa` gate.
