# InkCount v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace InkCount's geometric ink-cluster counter with deskew + scale-aware line segmentation + on-device handwriting recognition, and rebuild the page in a bento-grid soft-pastel design.

**Architecture:** Six focused ES modules under `web/src/` (decode, preprocess, segment, recognize, count, geometric) wired by `ui.js`, with `app.js` as a thin entry point. All assets vendored under `web/vendor/` so the page makes zero third-party requests. Two-stage UX: instant geometric estimate, replaced by the recognition count when the model is ready.

**Tech Stack:** OpenCV.js 4.9.0 (already vendored), transformers.js v3 + `Xenova/trocr-small-handwritten` q8 ONNX, onnxruntime-web WASM, libheif-js, vanilla JS/CSS.

## Global Constraints

- Spec of record: `docs/superpowers/specs/2026-08-06-inkcount-v2-design.md`. Algorithm parameters come from spec §4.2 verbatim.
- **No target, threshold, or pass/fail anywhere** in UI, code, or copy. InkCount reports a count.
- Zero backend, zero API keys, zero per-use cost. No third-party runtime requests — everything served from our own origin.
- All asset paths relative (`./…`); site must work at `https://dc-guo.github.io/inkcount/` and `http://localhost:8000/web/`.
- Every `cv.Mat`/`MatVector` released via the existing `withMats` scope pattern.
- Python files (`app.py`, `cv_utils.py`) are not modified; they become the labelled v1 prototype.
- Accuracy claims stay caveated until real photographs are in the suite (spec §7).
- Deploy is `git push origin main`; the Pages workflow uploads `web/` only.

### Task 2: `decode.js` — image and HEIC input

**Files:**
- Create: `web/src/decode.js`
- Create: `tests/decode.html`

**Interfaces:**
- Produces: `decodeToCanvas(fileOrBlob: Blob, maxEdge = 2000): Promise<HTMLCanvasElement>` — throws `Error` with a user-facing message on unsupported/corrupt input. `isHeic(buffer: ArrayBuffer): boolean`.

- [ ] **Step 1:** Implement `isHeic` by magic bytes, not extension or MIME type — browsers commonly report an empty `type` for `.heic`:

```js
export function isHeic(buffer) {
  const b = new Uint8Array(buffer, 0, Math.min(32, buffer.byteLength));
  if (String.fromCharCode(b[4], b[5], b[6], b[7]) !== 'ftyp') return false;
  const brand = String.fromCharCode(b[8], b[9], b[10], b[11]);
  return ['heic', 'heix', 'hevc', 'heim', 'heis', 'mif1', 'msf1'].includes(brand);
}
```

- [ ] **Step 2:** Implement `decodeToCanvas`: read the blob to an `ArrayBuffer`; if `isHeic`, lazily load libheif and decode the primary image to RGBA and put it on a canvas; otherwise use `createImageBitmap`. Then downscale so the long edge is ≤ `maxEdge`, preserving aspect ratio. Throw `new Error('That file could not be read as an image.')` when both paths fail.
- [ ] **Step 3:** Write `tests/decode.html` covering: a bundled JPEG decodes to the expected dimensions; a 3000px-wide JPEG downscales to long edge exactly 2000; a text file rejects with a readable message. Title reports `DECODE PASS`/`DECODE FAIL`.
- [ ] **Step 4:** Run it in the harness. Expected: `DECODE PASS`.

### Task 3: `preprocess.js` — deskew and de-rule

**Files:**
- Create: `web/src/preprocess.js`
- Create: `tests/preprocess.html`

**Interfaces:**
- Consumes: OpenCV.js global `cv`, `withMats` from `web/src/mats.js` (create it in this task by extracting `withMats`/`yieldUI` from the current `web/app.js`).
- Produces: `preprocess(canvas, scope) -> { gray: Mat, binary: Mat, textHeight: number, skewAngle: number }` — both Mats deskewed, tracked by `scope`.

- [ ] **Step 1:** Create `web/src/mats.js` exporting `withMats(fn)` and `yieldUI()`, moved verbatim from the current `web/app.js`.
- [ ] **Step 2:** Implement `preprocess` per spec §4.2 in this exact order — grayscale → CLAHE(2.0, 8×8) → blur 5×5 → `adaptiveThreshold(255, GAUSSIAN_C, BINARY_INV, 31, 15)` → `estimateSkew` → deskew gray **and** binary → `removeRuledLines` → `estimateTextHeight`. Order is load-bearing: de-ruling before deskew leaves fragments that become phantom text lines (measured: 25 phantom bands vs 15 real, +62% count error).
- [ ] **Step 3:** `estimateSkew(binary)`: resize ×0.35, for angle −6…+6 step 0.25 rotate and compute variance of the row-sum projection, return the argmax angle.
- [ ] **Step 4:** `removeRuledLines(binary)`: `MORPH_OPEN` with `(max(30, w/12), 1)` and `(1, max(30, h/12))` kernels, dilate the union 3×3, subtract from binary.
- [ ] **Step 5:** `estimateTextHeight(binary)`: `connectedComponentsWithStats`; median height of components with `3 ≤ h ≤ 0.1×imgH` and `area ≥ 12`; fall back to `max(8, imgH×0.01)` when none qualify.
- [ ] **Step 6:** `tests/preprocess.html`: loads `tests/fixtures/pages/03_skewed_photo.jpg`, asserts `skewAngle` is within ±0.75° of −3.5, and that `textHeight` is between 15 and 60. Title `PREPROCESS PASS`/`FAIL`.
- [ ] **Step 7:** Run in harness. Expected: `PREPROCESS PASS`.

### Task 4: `segment.js` — line bands and crops

**Files:**
- Create: `web/src/segment.js`
- Create: `tests/segment.html`

**Interfaces:**
- Consumes: `preprocess()` output.
- Produces: `segmentLines({ gray, binary, textHeight }, scope) -> Array<{ canvas: HTMLCanvasElement, rect: {x,y,w,h} }>`

- [ ] **Step 1:** Implement per spec §4.2 "Segment": smoothed row projection with box kernel `max(3, round(textHeight*0.6)|1)`; bands above `max(0.10*peak, 765)`; drop bands shorter than `0.55*textHeight`; drop bands whose ink area `< 0.9*textHeight²`; x-extent from first/last non-empty column ±10; crop from `gray` with vertical padding `0.45*textHeight`; return canvases via `cv.imshow`.
- [ ] **Step 2:** `tests/segment.html`: for each of the seven fixture pages, assert the detected line count is within ±2 of the expected value in `tests/fixtures/pages/expected.json`. Title `SEGMENT PASS`/`FAIL`.
- [ ] **Step 3:** Run in harness. Expected: `SEGMENT PASS`. Line counts should be 15 for pages 01–05 and 07, 20 for page 06.
